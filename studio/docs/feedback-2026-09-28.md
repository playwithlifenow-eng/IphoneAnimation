# First-use feedback — 28 September 2026

Source: Matt's two uploaded screen recordings, including the written notes beside the second recording. Review used sampled frames and the current source; it is not an Evaluate snapshot, a complete event replay, or an imported copy of Matt's working project.

## Observations and implementation findings

1. **3D frame much larger than the visible model.** Matt requests larger GLBs and a frame that follows the model more closely. The current frame is an independent DOM/WebGL viewport, not projected mesh bounds. Fitting includes every mesh in the GLB. Scene scale and camera distance change model occupancy without changing that frame. A useful improvement is explicit model fitting and clearer separation between viewport selection and object selection; do not silently crop animation or change accepted compositions.
2. **Hard to dismiss the frame or move the intended model.** Selection clears only when the pointer targets the canvas-board itself; empty space inside the composition does not clear it. Escape cancels a gesture but does not deselect. Separately, move/resize is rejected when affected properties have animation or signal owners. These are distinct problems and must not be presented as one user mistake.
3. **Rotation requires too much cursor movement.** Orbit uses a fixed 0.4 degrees per screen pixel and ignores editor zoom. Improve the interaction with predictable, adjustable sensitivity and verify at Matt's small canvas zoom. Retain one transaction per gesture.
4. **Overlapping GLBs are difficult to select.** Large transparent viewport rectangles can intercept selection. Matt has to use the Layers list to reach the intended GLB. Provide visible selection disambiguation or object hit testing without introducing a second property authority.

The notes refer to 00:40–00:50, 00:50–01:11 and 01:11–01:40 in the footage being reviewed; these are user-supplied references, not independently reconstructed event timestamps.

## Onboarding gaps

- Choreography needs a demonstrated two-key workflow, including the difference between static properties, time tracks and signal bindings.
- Scroll in the editor is a simulated 0–1 input slider. Exported runtime maps whole-document scroll to 0–1. It does not currently scrub the choreography timeline or offer section start/end ranges.
- Page extension currently requires increasing profile height and positioning another frame/content below existing content; there is no dedicated Add section workflow.
- Path is a visual editor for page-level X/Y animation keys, not a 3D camera path editor.
- Scene & look selects/filters 3D scene entities and exposes model/camera/light/material controls.
- Relations measure specified frame alignment/clearance. They report pass/fail/unknown and can draw connectors; they do not enforce constraints or measure mesh occlusion.
